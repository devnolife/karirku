4. Pertanyaan Teknis yang Mungkin Ditanya

Apa itu AI/LLM? Jelaskan dengan bahasa sederhana. (tes komunikasi!)
LLM itu seperti karyawan baru yang sudah membaca jutaan buku — pintar bicara dan menulis, tapi belum tahu apa-apa tentang perusahaan kita. Tugas saya sebagai AI engineer adalah "memberi dia akses ke dokumen perusahaan" dengan cara yang aman dan terkontrol, supaya jawabannya berdasarkan data kita, bukan karangan.
Apa itu RAG? Kenapa tidak fine-tuning saja?
RAG (Retrieval-Augmented Generation) itu: sebelum AI menjawab, sistem mencari dulu potongan dokumen yang relevan, lalu AI menjawab BERDASARKAN potongan itu. Analoginya: ujian open-book vs menghafal. RAG = open-book: lebih murah, datanya bisa di-update kapan saja cukup ganti dokumennya, dan jawabannya bisa ditelusuri sumbernya — penting untuk audit. Fine-tuning = menghafal: mahal, tiap ada data baru harus latih ulang, dan susah dijelaskan kenapa jawabannya begitu. Untuk kebutuhan dokumen perusahaan seperti SOP dan kontrak, RAG hampir selalu pilihan yang tepat. Saya sudah menjalankan pipeline RAG di produksi di fokusngajar.id.
Bonus point: ceritakan pengalaman InterOpera — kamu pernah bikin sistem evaluasi yang otomatis MENOLAK model hasil fine-tune karena akurasinya menurun. Itu bukti nyata kamu paham risiko fine-tuning.
Bagaimana kamu menangani AI yang menjawab ngawur (hallucination)?
  • Grounding: jawaban wajib bersumber dari dokumen (RAG) — kalau tidak ada di dokumen, AI dilatih menjawab "tidak ada informasinya".
  • Sitasi: tampilkan sumber/halaman dokumen di tiap jawaban, jadi user bisa verifikasi.
  • Evaluasi rutin: set pertanyaan uji + jawaban benar, dijalankan otomatis tiap ada perubahan (pengalaman InterOpera).
  • Guardrail: batasi topik, validasi output sebelum ditampilkan.
  • Human in the loop untuk keputusan penting — AI menyarankan, manusia memutuskan. (Sangat relevan untuk industri tambang/safety!)
Apa itu Responsible AI & explainability? (ADA DI REQUIREMENT — pasti ditanya)
Responsible AI artinya AI yang bisa dipertanggungjawabkan: jelas datanya dari mana, keputusannya bisa dijelaskan, tidak bocorkan data sensitif, dan ada manusia yang mengawasi. Di industri seperti pertambangan ini krusial — misal AI merekomendasikan penempatan tenaga kerja atau menilai laporan safety, kita harus bisa menjelaskan KENAPA, untuk audit dan keadilan. Praktik saya: selalu pakai pendekatan yang traceable (RAG dengan sitasi sumber), logging semua keputusan AI, data perusahaan tidak dipakai untuk melatih model publik, dan keputusan berisiko tinggi selalu lewat persetujuan manusia.
Python-mu sejauh apa? Framework AI apa yang kamu pakai?
Python saya pakai untuk backend AI dan data processing — utamanya FastAPI + Pydantic (contoh repo publik: aethra, amertasign-llm), pandas untuk olah data, dan integrasi OpenAI API. Untuk pipeline RAG saya pernah pakai kombinasi embedding model + vector database seperti Qdrant. Selain Python saya juga kuat di Go untuk backend AI performa tinggi — core-llm yang menggerakkan fokusngajar.id itu Go.
Jujur kalau ditanya PyTorch/TensorFlow deep-learning training dari nol: "Fokus saya di applied AI — memanfaatkan dan mengintegrasikan model (LLM, embedding, model siap pakai) menjadi solusi bisnis production-ready, bukan riset melatih model dari nol. Untuk kebutuhan bisnis GSI, pendekatan applied ini yang paling cepat memberi hasil."
Cloud apa yang kamu kuasai? Bagaimana deploy AI-mu?
Saya deploy di VPS Linux dan layanan cloud: Docker (multi-stage build), nginx, monitoring metrics, CI/CD. Backend AI fokusngajar.id saya kelola sendiri end-to-end di produksi. Saya juga terbiasa Vercel untuk frontend dan pernah menyusun sistem canary deployment untuk model AI — versi baru diuji otomatis dulu di sebagian traffic, kalau bagus dipromosikan, kalau jelek di-rollback otomatis.
Bagaimana kontrol biaya AI? (pertanyaan favorit orang bisnis)
  • Pilih model sesuai tugas — tugas ringan pakai model murah, tugas berat baru model mahal (bisa hemat 10-20x)
  • Rate limiting per user (saya implement dengan x/time di core-llm)
  • Caching jawaban untuk pertanyaan berulang
  • Batasi panjang konteks — kirim hanya potongan dokumen relevan, bukan semua
  • Monitoring penggunaan token per fitur, jadi ketahuan mana yang boros
Di fokusngajar.id saya pasang rate limiting dan pemilihan model per jenis tugas, jadi biaya API tetap terkendali meski pengguna bertambah.
Kalau kami minta PoC chatbot dokumen internal, berapa lama dan butuh apa?
Untuk PoC: 1–2 minggu. Yang saya butuhkan: contoh dokumen (misal 10–20 SOP/laporan), satu grup user uji coba, dan keputusan soal privasi — mau pakai API cloud (cepat, data keluar dengan enkripsi & perjanjian no-training) atau model lokal/self-hosted (data tidak keluar sama sekali, cocok untuk dokumen sensitif). Deliverable PoC: chatbot yang bisa dipakai tim uji + laporan akurasi + estimasi biaya kalau di-scale. Dari situ baru kita putuskan lanjut ke produksi atau tidak.
Jawaban terstruktur seperti ini (timeline + kebutuhan + deliverable + keputusan) yang membedakan engineer senior dari junior di mata user bisnis.
Bisa computer vision? (misal deteksi APD/helm di area tambang)
Bukan spesialisasi utama saya, tapi bisa dieksekusi — untuk deteksi objek seperti APD sudah ada model siap pakai (YOLO dan sejenisnya) yang tinggal di-fine-tune dengan foto dari lapangan. Pendekatan saya realistis: mulai PoC dengan model pre-trained, ukur akurasinya dengan data GSI sendiri, baru putuskan investasi lebih jauh. Saya tidak akan menjanjikan akurasi sebelum lihat datanya.
Live coding / diminta demo di laptop
  • Demo utama: fokusngajar.id (live, buka di browser) + tunjukkan arsitektur core-llm & interopera-platform di GitHub
  • Kalau disuruh coding: kemungkinan Python sederhana — parsing data, hit API, logika bisnis. Tenang, kerjakan sambil berpikir keras (thinking out loud) — user menilai cara berpikirmu, bukan cuma hasilnya
  • Kalau boleh pakai tools sendiri, bilang jujur: "sehari-hari saya pakai AI assistant untuk mempercepat, tapi saya paham setiap baris yang dihasilkan" — justru nilai plus untuk posisi AI Engineer

5. Pertanyaan Bisnis / Use Case (dari sisi "User")

Menurut kamu, AI bisa dipakai untuk apa di perusahaan tambang seperti kami?

INI PERTANYAAN PALING PENTING. Jawab terstruktur, mulai dari yang paling cepat memberi hasil:

Saya bagi tiga berdasarkan kecepatan hasil. Cepat (1–2 bulan): asisten dokumen internal — SOP, kontrak, regulasi bisa ditanya lewat chat; dan otomasi laporan produksi. Menengah (3–6 bulan): AI untuk proses HR/manpower — screening pelamar, matching tenaga kerja ke proyek; analisis dokumen tender. Jangka panjang: predictive maintenance alat berat dan monitoring safety berbasis kamera — ini butuh pengumpulan data dulu. Saran saya mulai dari asisten dokumen, karena datanya sudah ada, risikonya rendah, dan hasilnya langsung terasa oleh banyak divisi.
Berapa biaya membangun solusi AI? Mahal tidak?
Tidak semahal yang dibayangkan kalau pendekatannya benar. PoC asisten dokumen misalnya, biaya berjalannya bisa mulai dari ratusan ribu sampai beberapa juta rupiah per bulan untuk API — tergantung pemakaian. Yang mahal itu kalau langsung bangun besar tanpa validasi. Makanya saya selalu mulai PoC kecil, ukur hasilnya, baru scale. Dan satu hal: saya punya lisensi tooling development sendiri, jadi tidak ada biaya tambahan untuk itu.
Data perusahaan kami sensitif. Aman tidak pakai AI?
Pertanyaan yang tepat. Ada tiga tingkat: (1) pakai API enterprise yang punya perjanjian data tidak dipakai untuk training — cukup untuk mayoritas kasus; (2) dokumen sangat sensitif bisa difilter/di-mask dulu sebelum ke AI; (3) paling ketat: model self-hosted di server sendiri — data tidak pernah keluar. Saya bisa implementasikan ketiganya, dan pemilihan tingkatnya kita putuskan bersama per jenis dokumen.
Bagaimana kami tahu proyek AI-nya berhasil? (ukuran sukses)
Sebelum mulai, kita sepakati metrik: misal akurasi jawaban di atas X% dari set pertanyaan uji, waktu pencarian dokumen turun dari sekian menit jadi sekian detik, atau jam kerja admin yang dihemat per minggu. Tiap PoC saya tutup dengan laporan berisi angka-angka itu, jadi keputusan lanjut/tidaknya berdasarkan data, bukan perasaan.
